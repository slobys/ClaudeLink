# macOS 客户端

Mac 版用于自动配置 Claude Code 的网络与运行环境：按保存的设置建立连接、准备临时环境、执行检查并启动；结束会话后尝试恢复原设置。

支持 macOS 15 或更新版本。Apple 芯片下载 arm64，Intel 下载 x64；苹果菜单 → 关于本机可以查看芯片。无需安装 .NET，也无需另开代理客户端。

## 安装

1. 从本项目 GitHub Releases 下载对应 DMG，打开后将 Claude Link 拖入“应用程序”。也可放入个人 `~/Applications` 文件夹，方便当前用户在线更新。
2. 当前发布采用 ad-hoc 代码签名，没有 Apple Developer ID 公证。系统可能拦截首次打开；核对下载来源和 SHA-256 后，在“系统设置 → 隐私与安全性”按 macOS 提供的“仍要打开”流程确认。不要关闭 Gatekeeper。
3. 首次保存配置会在登录钥匙串中创建配置密钥；节点、密码和订阅地址通过 AES-GCM 加密保存在 `~/Library/Application Support/ClaudeLink/settings.dat`。请保留钥匙串中的对应密钥。更新后系统可能再次询问钥匙串访问权限。
4. 另行安装官方 Claude 桌面应用或 Claude Code CLI。桌面应用选择 `.app`，CLI 选择 `claude` 可执行文件，两者独立设置。

## 网络与启动

- 添加节点：粘贴分享链接、sing-box JSON、Base64 或兼容的 Clash YAML。支持协议与 Windows 使用相同解析器。编辑节点可修改名称和原始出站配置。
- 添加订阅：填写名称及 HTTP/HTTPS 地址，点击保存并更新；失败时保留原节点。连接期间禁止修改当前节点配置。
- 官方桌面模式强制使用 TUN，连接时出现 macOS 管理员授权窗口。授权只用于这次内核及环境会话，不安装常驻 root 服务。通过官方 `claude://code/new?folder=...` 请求打开 Code 页面，账户、项目确认和桌面语言由 Claude 管理。
- CLI 模式可以关闭 TUN，独立终端携带代理和所选语言环境。用完后在启动器点击断开；终端退出不会自动结束本地代理。
- 本地混合代理只监听 127.0.0.1。TUN 会影响整台电脑路由；启动器不改 macOS 系统 HTTP 代理。不同时使用其他 TUN 客户端。
- 浏览器核对默认优先 Chrome，也可选 Edge。使用独立浏览器配置应用所选语言，只打开 `https://ip.net.coffee/claude/`，默认开启网页的隐藏 IP，刷新后重新应用；可在网页设备信息核对语言。隐藏 IP 只影响页面显示。只为当前独立窗口设置代理，不修改日常 Chrome 配置。



## 节点与链路选择

节点管理使用地区卡片，支持名称搜索、地区和分组筛选。国旗按节点名称识别，实际出口仍以连接检测为准。点击卡片即可选择，连接期间需先断开再切换。

“创建链式代理”用于配置 **本机 → 入口节点 → 最终出口 → 目标网站**。先添加入口和出口，再分别选择并保存；住宅 IP 通常使用 HTTP / HTTPS / SOCKS 出口。当前支持双跳及基于 TCP 传输的出口协议，HTTP 出口不提供 UDP 转发。链路引用失效时会提示修改，不会自动更换出口。

## 临时设置与恢复

首次安装默认勾选 TUN、严格网络预检、临时关闭 IPv6 和匹配系统时区，语言 en-US，浏览器自动优先 Chrome。更新保留用户已保存的明确选择。安装本身不改网络，临时系统选项在点击连接后需要 TUN 管理员会话。仅对活动 `en*` 物理网络服务处理 IPv6；支持自动、关闭和仅本地链路三种原状态。手动 IPv6 配置无法完整恢复时，修改前停止并提示用户。时区仅在获得有效出口地区结果后请求修改，第三方数据无法验证时不改。

root 后台在 `/private/var/db/ClaudeLink/Sessions/<UUID>` 保存权限受限的配置和恢复日志，公开状态不含节点信息。监控启动器 PID 与启动时间，正常断开或启动器退出后停止内核并恢复。突然断电或后台崩溃时，下次打开会请求授权恢复；恢复未完成时拦截新连接。若用户或其他程序在会话中改变环境，恢复操作不会覆盖已经不同的当前状态。

恢复完成后移除临时明文配置、内核日志和暂存内核可执行文件；只保留不含凭据的会话状态、空恢复日志和小型恢复助手以供确认。不要手动删除尚未恢复的后台记录。登录钥匙串锁定或配置损坏时，启动器保留原文件并阻止覆盖保存。

## 检测结果

API HTTP 401 只说明 HTTPS 请求到达服务，不能证明账户授权。Claude 登录页自动探测使用 `https://claude.ai/login`；HTTP 403 独立显示为注意，严格预检不通过，提示用浏览器确认，不代表 Chrome 无法打开。出口地区来自第三方信息，仅供参考。新启动确认 sheet 区分 API 结果与未通过项目，默认返回检查，不会把未知结果或继续启动视为通过。

1.2.2 的更新检查优先使用 GitHub 最新正式发布的签名清单直链，避开匿名 REST API 查询额度；直链网络失败时才尝试 API 入口。清单签名和 ZIP 哈希仍需通过校验，签名失败不尝试其他来源。旧版更新检查遇到接口限流时，先从发布页面下载对应芯片的 DMG 覆盖安装一次，保留已有配置。

## 在线更新

启动时检查正式 GitHub Release，发现更新显示下载按钮。签名使用内置 ECDSA 公钥，下载后校验大小、SHA-256、应用标识、版本与代码签名完整性。安装前恢复网络环境，再等待旧进程退出并替换应用；保留旧应用备份，配置不放在应用包内。

当前用户可写的安装目录支持“安装并重启”。若管理员管理的“应用程序”目录不可写，会打开已验证更新目录，提示拖入覆盖；不会静默提权覆盖系统目录。DMG 内直接运行时请先拖入安装目录。没有 Apple 公证时，更新后的系统安全确认仍以 macOS 提示为准。

## 验证边界

原生 CI 验证两种架构编译、节点桥接、官方内核配置、钥匙串加密、签名拒绝、root 后台的本地代理生命周期与恢复以及原生页面渲染。CI 的后台测试只访问回环地址，不更改物理网卡、系统时区或默认路由。真实节点、用户 Mac 的 TUN 路由、管理员授权界面、Claude 登录与完整更新覆盖流程需要在用户 Mac 上实测；不能用 CI 构建成功替代这些结论。
